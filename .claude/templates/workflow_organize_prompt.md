# 業務整理 プロンプトテンプレート

> 用途: 散らかった業務・タスク・情報をClaudeと整理し、再利用可能な形にまとめる
> 使い方: `< >` の部分を自分の状況に合わせて書き換えてから使う

---

## 探索フェーズ（業務の現状把握）

```
以下の業務について、整理を始める前に現状を把握してください。

【対象業務】<例: 新人研修の企画・運営業務>
【関係者】<例: 人材育成担当2名、各部門トレーナー>
【現状の問題感】<例: 毎回ゼロから作り直している、引き継ぎがうまくいかない>
【持っている資料・情報】<例: 昨年の研修資料、アンケート結果、タスクリストのメモ>

整理してほしい観点:
1. この業務の構成要素（何をやっているか）の洗い出し
2. 繰り返し発生しているタスクの候補
3. 属人化・ブラックボックス化している箇所の推測
4. 整理後に「あると嬉しい成果物」の候補

まだ整理や再構成はしないでください。
```

---

## 計画フェーズ（整理方針の決定）

```
以下の業務を整理するための方針を作成してください。

【対象業務】<　>
【整理のゴール】<例: 誰でも引き継げるマニュアルを作る / テンプレートを揃える>
【優先順位】<例: 繰り返し頻度の高いものから / 引き継ぎリスクの高いものから>

各整理ステップについて以下を明記してください:
- 対象（何を整理するか）
- 成果物の形式（マニュアル / チェックリスト / テンプレート / フロー図）
- 完了の判断基準

まだ実際の整理は行わないでください。
```

---

## 実行フェーズ（1業務ずつ整理）

```
「<業務名>」だけを整理してください。
以下のいずれかの形式で出力してください（指定がなければ最適なものを選ぶ）:

【チェックリスト形式】
- やること・確認することを順番に列挙

【手順書形式】
- 目的 / 対象者 / 前提条件 / 手順（番号付き） / 完了条件

【テンプレート形式】
- 空欄を埋めるだけで使えるフォーマット

整理後、変更点・確認方法・次の候補業務を要約してください。
```

---

## レビューフェーズ（整理結果の評価）

```
整理した業務資料を以下の観点でレビューしてください:

1. 【引き継ぎ可能性】この資料を渡せば別の人が同じ業務をできるか
2. 【抜け漏れ】実際の業務で発生しうるが書かれていない手順・判断はないか
3. 【再利用性】他の業務・プロジェクトに転用できる部分はあるか
4. 【簡略化余地】削っても問題ない情報・冗長な箇所はないか
5. 【テンプレート昇格候補】`.claude/templates/` に保存すべきパーツを指摘する
```

## タスク棚卸しプロンプト（週次・月次の業務整理に）

```
以下のタスク一覧を整理してください。

【タスク一覧】
<箇条書きでタスクを貼り付ける>

整理してほしいこと:
1. 緊急度・重要度で4分類（今すぐ / 計画 / 委任 / 保留）
2. 繰り返しタスクの抽出（テンプレート化候補）
3. 削除・省略できるタスクの提案
4. 今週中に完了すべき3件の優先候補

分類後、判断の根拠も簡潔に示してください。
```

## 情報・ログ整理プロンプト

```
以下の情報（メモ・議事録・チャット履歴など）を整理してください。

【情報の種類】<例: 先週のミーティングメモ3件>
【整理のゴール】<例: 次のアクションを明確にする / 資料として保存できる形にする>

【情報本文】
<ここに貼り付ける>

整理してほしい観点:
- 決定事項・合意内容
- 未決定事項・宿題
- 次のアクションと担当者
- 保存・共有が必要な情報

箇条書きでコンパクトにまとめてください。
```
